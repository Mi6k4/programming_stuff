DML и DLL

Data Definition Language (DDL) – это группа операторов определения данных. 
Другими словами, с помощью операторов, входящих в эту группы, мы определяем структуру базы данных и работаем с объектами этой базы, т.е. создаем, изменяем и удаляем их

CREATE – используется для создания объектов базы данных;
ALTER – используется для изменения объектов базы данных;
DROP – используется для удаления объектов базы данных.


Data Manipulation Language (DML) – это группа операторов для манипуляции данными. 
С помощью этих операторов мы можем добавлять, изменять, удалять и выгружать данные из базы, т.е. манипулировать ими.

SELECT – осуществляет выборку данных;
INSERT – добавляет новые данные;
UPDATE – изменяет существующие данные;
DELETE – удаляет данные


Data Control Language (DCL) – группа операторов определения доступа к данным. Иными словами, это операторы для управления разрешениями, 
с помощью них мы можем разрешать или запрещать выполнение определенных операций над объектами базы данных.

GRANT – предоставляет пользователю или группе разрешения на определённые операции с объектом;
REVOKE – отзывает выданные разрешения;
DENY– задаёт запрет, имеющий приоритет над разрешением.


В SQL для этого применяются специальные агрегатные функции. К наиболее часто применяемым можно отнести функции SUM, MIN, MAX, AVG и COUNT.

Оконная функция в SQL - функция, которая работает с выделенным набором строк (окном, партицией) и выполняет вычисление для этого набора строк в отдельном столбце. 

Партиции (окна из набора строк) - это набор строк, указанный для оконной функции по одному из столбцов или группе столбцов таблицы. 
Партиции для каждой оконной функции в запросе могут быть разделены по различным колонкам таблицы.


Основное отличие WHERE от HAVING заключается в том, что WHERE сначала выбирает строки, а затем группирует их и вычисляет агрегатные функции 
(таким образом, она отбирает строки для вычисления агрегатов), тогда как HAVING отбирает строки групп после группировки и вычисления агрегатных функций

INNER JOIN:

Описание: Возвращает только те строки, у которых есть совпадение в обеих таблицах.


SELECT A.*, B.*
FROM TableA A
INNER JOIN TableB B ON A.common_column = B.common_column;



LEFT JOIN (или LEFT OUTER JOIN):

Описание: Возвращает все строки из левой таблицы и совпадающие строки из правой таблицы.
 Если совпадения нет, возвращаются NULL для правой таблицы.

SELECT A.*, B.*
FROM TableA A
LEFT JOIN TableB B ON A.common_column = B.common_column;



RIGHT JOIN (или RIGHT OUTER JOIN):

Описание: Возвращает все строки из правой таблицы и совпадающие строки из левой таблицы. 
Если совпадения нет, возвращаются NULL для левой таблицы.


SELECT A.*, B.*
FROM TableA A
RIGHT JOIN TableB B ON A.common_column = B.common_column;



FULL OUTER JOIN:

Описание: Возвращает все строки, когда есть совпадение в одной из таблиц. 
Если совпадения нет, возвращаются NULL для столбцов, где нет совпадения.


SELECT A.*, B.*
FROM TableA A
FULL OUTER JOIN TableB B ON A.common_column = B.common_column;



Заключение
INNER JOIN возвращает только совпадающие строки из обеих таблиц.
LEFT JOIN возвращает все строки из левой таблицы и совпадающие строки из правой таблицы, с NULL для правой таблицы, если совпадения нет.
RIGHT JOIN возвращает все строки из правой таблицы и совпадающие строки из левой таблицы, с NULL для левой таблицы, если совпадения нет.
FULL OUTER JOIN возвращает все строки из обеих таблиц, с NULL для отсутствующих значений в столбцах, где нет совпадения.



Подзапросы (subqueries) в SQL — это запросы, вложенные внутри других запросов. Они могут быть использованы в различных частях основного запроса,
 таких как SELECT, FROM, WHERE, HAVING, или JOIN операторов.
 Подзапросы позволяют выполнять вложенные операции и могут быть коррелированными или некоррелированными.

Некоррелированные подзапросы
Некоррелированный подзапрос — это подзапрос, который может быть выполнен независимо от внешнего запроса. 
Он не зависит от данных внешнего запроса и выполняется один раз для получения результата, который затем используется во внешнем запросе.


Пример 1: Подзапрос в WHERE

SELECT name
FROM employees
WHERE department_id = (SELECT id FROM departments WHERE name = 'HR');

В этом примере подзапрос выполняется один раз для получения id отдела с именем 'HR', и результат используется в основном запросе для фильтрации сотрудников.

Пример 2: Подзапрос в FROM


SELECT avg_salary
FROM (
    SELECT department_id, AVG(salary) as avg_salary
    FROM employees
    GROUP BY department_id
) AS dept_avg_salaries
WHERE department_id = 1;

В этом примере подзапрос создаёт временную таблицу с средними зарплатами по отделам, и внешний запрос выбирает среднюю зарплату для отдела с department_id равным 1.




Коррелированные подзапросы
Коррелированный подзапрос — это подзапрос, который выполняется для каждой строки внешнего запроса и использует значения из внешнего запроса.
 Он зависит от данных внешнего запроса и выполняется многократно.


Пример 1: Коррелированный подзапрос в WHERE

SELECT e1.name, e1.salary
FROM employees e1
WHERE e1.salary > (SELECT AVG(e2.salary)
                   FROM employees e2
                   WHERE e2.department_id = e1.department_id);


В этом примере коррелированный подзапрос выполняется для каждой строки основного запроса и возвращает среднюю зарплату для каждого отдела, 
сравнивая её с зарплатой текущего сотрудника.


Пример 2: Коррелированный подзапрос в SELECT

SELECT name,
       (SELECT COUNT(*)
        FROM employees e2
        WHERE e2.manager_id = e1.id) AS num_subordinates
FROM employees e1;
В этом примере коррелированный подзапрос выполняется для каждой строки основного запроса и подсчитывает количество подчинённых для каждого менеджера.



Использование подзапросов
Подзапрос в SELECT:

Подзапрос возвращает одно значение, которое используется в списке выборки основного запроса.

SELECT name,
       (SELECT MAX(salary)
        FROM employees) AS max_salary
FROM employees;


Подзапрос в FROM:

Подзапрос создаёт временную таблицу, которая используется в основном запросе.
s
SELECT d.name, avg_salaries.avg_salary
FROM departments d
JOIN (
    SELECT department_id, AVG(salary) as avg_salary
    FROM employees
    GROUP BY department_id
) AS avg_salaries
ON d.id = avg_salaries.department_id;


Подзапрос в WHERE:

Подзапрос используется для фильтрации строк в основном запросе.

SELECT name
FROM employees
WHERE department_id = (SELECT id FROM departments WHERE name = 'HR');


Подзапрос в HAVING:

Подзапрос используется для фильтрации групп данных, сформированных с помощью GROUP BY.

SELECT department_id, AVG(salary) as avg_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) > (SELECT AVG(salary) FROM employees);


Подзапросы являются мощным инструментом для создания сложных запросов в SQL, позволяя выполнять вложенные операции и улучшать гибкость и выразительность запросов.





Индексы в базах данных
Индексы в базах данных — это специальные структуры данных, которые позволяют ускорить операции поиска и сортировки данных. Они работают подобно указателям или индексам в книгах, 
позволяя быстро находить нужную информацию без необходимости просматривать всю таблицу. Индексы существенно влияют на производительность запросов, особенно в больших таблицах.

Влияние индексов на производительность
Ускорение запросов:

SELECT-запросы: Индексы значительно ускоряют операции поиска и извлечения данных.
ORDER BY и GROUP BY: Использование индексов может ускорить сортировку и группировку данных.
JOIN: Индексы помогают быстрее находить соответствующие строки при объединении таблиц.
Затраты на обновление данных:

INSERT, UPDATE, DELETE: Индексы требуют дополнительных ресурсов для поддержания актуальности. 
При изменении данных индексы также должны быть обновлены, что может замедлить операции изменения данных.

Кластеризованные и некластеризованные индексы
Кластеризованные индексы (Clustered Indexes):

Описание:

Кластеризованный индекс определяет физический порядок хранения данных в таблице. Каждая таблица может иметь только один кластеризованный индекс, 
так как данные могут быть упорядочены только одним способом.
Строки данных таблицы упорядочены на диске в соответствии с кластеризованным индексом.
Преимущества:

Быстрая выборка данных при использовании поиска по кластеризованному индексу.
Эффективен для диапазонных запросов (BETWEEN, >, <), так как данные физически упорядочены.
Недостатки:

Вставка, обновление и удаление данных могут быть более медленными, так как требуется перемещение данных для поддержания порядка.
Крупные операции сортировки и перетасовки данных могут быть ресурсозатратными.


Некластеризованные индексы (Non-clustered Indexes):

Описание:

Некластеризованный индекс создает отдельную структуру, которая хранит указатели на физические строки данных. Таблица может иметь множество некластеризованных индексов.
Структура индекса содержит ключевые значения и указатели на соответствующие строки данных.
Преимущества:

Быстрая выборка данных для конкретных значений.
Позволяет создать несколько индексов для различных столбцов или комбинаций столбцов.
Недостатки:

Дополнительное использование дискового пространства для хранения структуры индекса.
Поддержание актуальности индексов требует дополнительных ресурсов при изменении данных.


Выбор между кластеризованными и некластеризованными индексами
Когда использовать кластеризованный индекс:

Когда столбец используется часто для диапазонных запросов.
Когда столбец является уникальным идентификатором строки.
Когда необходимо часто упорядочивать данные по этому столбцу.


Когда использовать некластеризованный индекс:

Когда необходимо ускорить поиск по конкретному столбцу или комбинации столбцов.
Когда таблица уже имеет кластеризованный индекс и требуется дополнительный индекс для других частых запросов.
Когда необходимо поддерживать несколько различных индексов для различных типов запросов.




Оптимизация SQL-запросов является важным шагом для обеспечения эффективной работы баз данных. 
Она включает в себя ряд методов и стратегий, включая создание индексов, правильное написание запросов и анализ выполнения запросов с помощью EXPLAIN планов. 
Вот основные способы оптимизации SQL-запросов:

1. Использование индексов
Индексы позволяют ускорить выполнение запросов, особенно при поиске, сортировке и объединении данных. 
Необходимо создавать индексы для столбцов, которые часто используются в условиях WHERE, JOIN, ORDER BY и GROUP BY. 
Однако избегайте создания слишком много индексов, так как это может ухудшить производительность при вставке, обновлении и удалении данных.

2. Правильное написание запросов
Избегайте использования операторов SELECT *, выбирайте только необходимые столбцы.
Пишите простые и читаемые запросы.
Используйте согласованные имена столбцов и таблиц.
Оптимизируйте условия WHERE, избегайте использования функций в условиях.
Используйте подзапросы и встроенные функции агрегации только тогда, когда это необходимо.


3. Использование EXPLAIN планов
EXPLAIN планы позволяют анализировать, как база данных выполняет запросы, и определять, какие индексы используются, какие операции выполняются и какие таблицы объединяются. Это помогает идентифицировать проблемные места и оптимизировать запросы. При анализе EXPLAIN планов обращайте внимание на следующие показатели:

Используемые индексы.
Типы объединений (Nested Loop, Hash Join, Merge Join).
Оценки стоимости и количества строк для каждой операции.




Команда EXPLAIN в SQL используется для получения плана выполнения запроса без его фактического выполнения.
 Это позволяет анализировать и оптимизировать запросы без риска внесения изменений в данные. В зависимости от используемой СУБД синтаксис
 и вывод могут немного отличаться, но основной принцип остается тем же.

Пример использования команды EXPLAIN:


EXPLAIN SELECT * FROM employees WHERE department_id = 1;

Результат выполнения команды EXPLAIN будет содержать информацию о порядке выполнения запроса, используемых индексах,
 типах объединений и прочие подробности, которые помогут в оптимизации запроса.


Команда ANALYZE
Команда ANALYZE также используется для анализа выполнения запроса, 
но она также фактически выполняет запрос и собирает статистику о производительности. 
Это может быть полезно для оценки времени выполнения запроса и определения реального количества обработанных строк.


Копировать код
ANALYZE SELECT * FROM employees WHERE department_id = 1;

Результат выполнения команды ANALYZE будет включать в себя ту же информацию, что и результат команды EXPLAIN
, но также будет содержать дополнительную статистику о времени выполнения запроса.


Анализ плана выполнения запроса

При анализе плана выполнения запроса обращайте внимание на следующие ключевые моменты:

Использование индексов: Проверьте, используются ли индексы для фильтрации или сортировки данных.

Типы объединений: Оцените типы объединений (Nested Loop, Hash Join, Merge Join) и их порядок выполнения.

Оценка количества строк: Проверьте, как оценивается количество строк для каждой операции и как это может влиять на производительность.

Оценка стоимости операций: Проанализируйте оценки стоимости операций и их влияние на общее время выполнения запроса.

Индикаторы времени выполнения: В случае использования команды ANALYZE обратите внимание на показатели времени выполнения запроса для оценки его производительности.

Анализируя план выполнения запроса, можно идентифицировать узкие места, оптимизировать запросы и улучшить производительность базы данных.
